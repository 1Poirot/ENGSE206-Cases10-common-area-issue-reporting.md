# 11 — Conceptual Architecture

> **Week 11 deliverable**

## 1. Architecture Overview

ระบบแจ้งปัญหาพื้นที่ส่วนกลางและติดตามการแก้ไขออกแบบโดยใช้ Layered Architecture ซึ่งแบ่งการทำงานออกเป็น 3 ชั้นหลัก ได้แก่

- Presentation Layer ทำหน้าที่แสดงผลและรับข้อมูลจากผู้ใช้งาน เช่น การแจ้งปัญหา การดูสถานะ และการตรวจสอบประวัติ
- Application / Service Layer ทำหน้าที่ประมวลผลคำขอ ตรวจสอบข้อมูล จัดการสิทธิ์ และควบคุมการทำงานของระบบ เช่น การรับเรื่อง การมอบหมายงาน และการเปลี่ยนสถานะ
-  Data Layer ทำหน้าที่จัดเก็บและเรียกใช้ข้อมูลของระบบ เช่น ข้อมูลผู้ใช้งาน รายการแจ้งปัญหา สถานที่ ประเภทปัญหา รูปภาพ สถานะ และประวัติการดำเนินงาน

การแบ่งระบบออกเป็นแต่ละชั้นช่วยให้หน้าที่ของระบบมีความชัดเจน ลดการเชื่อมโยงระหว่างส่วนต่าง ๆ และช่วยให้สามารถพัฒนา แก้ไข และบำรุงรักษาระบบได้ง่ายขึ้น

ลำดับการทำงาน

ผู้ใช้งาน
→ Web / User Interface
→ Application / API
→ Business Logic
→ Database / File Storage

ระบบกำหนดการเข้าถึงฟังก์ชันตามบทบาทของผู้ใช้งาน ดังนี้

ผู้แจ้งปัญหา สามารถแจ้งปัญหา ดูสถานะ และตรวจสอบประวัติรายการที่ตนเองแจ้ง
เจ้าหน้าที่ สามารถรับเรื่อง ตรวจสอบรายละเอียด ดำเนินการ และปรับปรุงสถานะของปัญหา
ผู้ดูแลระบบ สามารถจัดการข้อมูลผู้ใช้งาน สิทธิ์ และข้อมูลพื้นฐานของระบบตามขอบเขตที่กำหนด

## 5. Architecture Rationale

- เลือกใช้ Layered Architecture เนื่องจากระบบแจ้งปัญหามีการทำงานหลายส่วน เช่น การแจ้งปัญหา การจัดการรายการ การอัปเดตสถานะ และการกำหนดสิทธิ์ของผู้ใช้งาน จึงแบ่งการทำงานออกเป็นแต่ละ Layer เพื่อให้จัดการได้ง่ายและเป็นระบบ
- Presentation Layer รองรับการใช้งานของผู้แจ้งปัญหา เจ้าหน้าที่ และผู้ดูแลระบบ โดยแต่ละบทบาทสามารถเข้าถึงฟังก์ชันที่แตกต่างกัน
- Application / Service Layer ใช้ประมวลผลรายการแจ้งปัญหา เช่น ตรวจสอบข้อมูล กำหนดสิทธิ์ มอบหมายงาน และอัปเดตสถานะของปัญหา
- Data Layer ใช้จัดเก็บข้อมูลรายการแจ้งปัญหา หมายเลขรายการ สถานะ ประวัติ และข้อมูลผู้ใช้งาน ทำให้สามารถติดตามรายการแต่ละรายการได้อย่างเป็นระบบ
- ข้อดี: ช่วยให้ระบบแจ้งปัญหามีโครงสร้างชัดเจน สามารถควบคุมสิทธิ์และสถานะของรายการได้ง่าย และสะดวกต่อการแก้ไขหรือพัฒนาฟังก์ชันเพิ่มเติมในอนาคต
- ข้อจำกัด: การแบ่งระบบเป็นหลาย Layer ทำให้ต้องมีการกำหนดการเชื่อมต่อระหว่างแต่ละส่วนอย่างชัดเจน และอาจเพิ่มขั้นตอนในการพัฒนาระบบ

## 6. Quality Attribute Evaluation Questions

- Data Integrity: ระบบสามารถป้องกันไม่ให้หมายเลขรายการแจ้งปัญหาซ้ำกันได้อย่างไร?
- Security: ระบบสามารถกำหนดสิทธิ์การใช้งานให้เหมาะสมกับผู้แจ้งปัญหา เจ้าหน้าที่ และผู้ดูแลระบบได้อย่างไร?
-  Traceability: ระบบสามารถแสดงสถานะและประวัติการดำเนินงานของรายการแจ้งปัญหาให้ผู้แจ้งติดตามได้อย่างไร?
- Usability: ผู้ใช้งานสามารถแจ้งปัญหาและตรวจสอบสถานะของรายการได้ง่ายและไม่ซับซ้อนหรือไม่?
- Accessibility: ระบบสามารถรองรับการใช้งานผ่านคอมพิวเตอร์และโทรศัพท์มือถือได้อย่างไร?
- Maintainability: การแบ่งระบบเป็น Layer ช่วยให้สามารถแก้ไขหรือเพิ่มฟังก์ชันของระบบแจ้งปัญหาในอนาคตได้อย่างไร?
