## 2. Issues / Holds

| Issue ID     | เรื่องที่ต้อง Hold                              | เหตุผล                                                                                                | สิ่งที่ต้องเก็บเพิ่ม                                  |
| ------------ | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| **ISSUE-01** | เกณฑ์การตรวจจับและรวมรายการแจ้งปัญหาซ้ำ         | E-07 ระบุเพียงว่าปัญหาเดียวกันอาจมีผู้แจ้งหลายคน แต่ยังไม่มีเกณฑ์ที่ยืนยันว่ารายการใดควรถูกรวม        | เกณฑ์ Duplicate Detection และ Decision จากเจ้าหน้าที่ |
| **ISSUE-02** | เกณฑ์การจัดระดับความเร่งด่วนและ Safety Priority | E-04 และ E-05 สนับสนุนแนวคิดเรื่อง Priority แต่ยังไม่มีตัวเลขหรือเกณฑ์ที่ยืนยันสำหรับแต่ละระดับ       | Priority Policy / Safety Criteria                     |
| **ISSUE-03** | Workflow การมอบหมายและโอนงาน                    | RC-07 ถูกเสนอเป็น Candidate แต่ยังไม่มีข้อมูลยืนยันว่าใครสามารถมอบหมายหรือโอนงาน และในกรณีใด          | Assignment Workflow + Authority Matrix                |
| **ISSUE-04** | รายละเอียด Role และ Permission                  | E-08 สนับสนุนการควบคุมสิทธิ์ตามบทบาท แต่ยังไม่มีรายละเอียด Permission ของแต่ละ Role                   | Role-Permission Matrix                                |
| **ISSUE-05** | รายละเอียด Audit Log                            | RC-05 ระบุผู้ดำเนินการ วันเวลา และการเปลี่ยนแปลง แต่ยังต้องยืนยันว่าการดำเนินการประเภทใดต้องถูกบันทึก | Audit Policy / Decision จาก Owner                     |
| **ISSUE-06** | รูปแบบ Notification                             | RC-02 ระบุว่าควรแจ้งเตือนเมื่อสถานะเปลี่ยน แต่ยังไม่มีหลักฐานยืนยันช่องทางหรือเงื่อนไขการแจ้งเตือน    | Notification Policy และ Channel ที่ได้รับการยืนยัน    |
| **ISSUE-07** | รูปแบบรายงานและข้อมูลที่ต้องสรุป                | E-09 ระบุความต้องการค้นหา กรอง และสรุปข้อมูล แต่ยังไม่ได้กำหนดรายละเอียดของ Report                    | ตัวอย่าง Report / Stakeholder Decision                |

> **หลักการ Hold:** ประเด็นที่อยู่ในรายการนี้ยังไม่ควรถูกกำหนดเป็นกฎเชิงรายละเอียดหรือตัวเลขในระบบ จนกว่าจะมี Evidence หรือ Decision จากผู้เกี่ยวข้องที่สามารถตรวจสอบได้

## 3. Follow-up Plan

| Action                                           | Output ที่ต้องได้                     | ใช้ต่อใน Week06 อย่างไร                        |
| ------------------------------------------------ | ------------------------------------- | ---------------------------------------------- |
| สัมภาษณ์เจ้าหน้าที่อาคารเพิ่มเติม                | Required Fields ของแบบฟอร์มแจ้งปัญหา  | Acceptance Criteria และ Use Case Preconditions |
| สอบถามผู้ดูแลความปลอดภัยเรื่อง Priority          | Priority Criteria และ Safety Criteria | Priority Rule และ Alternate Flow               |
| สอบถามเจ้าหน้าที่เรื่อง Duplicate Issue          | เกณฑ์ตรวจจับและรวมรายการซ้ำ           | Duplicate Detection และ Data Integrity Rule    |
| ขอ Role-Permission Matrix จากผู้ดูแลระบบ         | รายละเอียดสิทธิ์แต่ละ Role            | Access Control และ Quality Scenario            |
| ขอรายละเอียด Audit Log                           | รายการ Action ที่ต้องบันทึก           | Auditability Acceptance Criteria               |
| สอบถาม Workflow การมอบหมายงาน                    | Assignment / Transfer Rule            | FR-06 และ Alternate Flow                       |
| ขอรูปแบบรายงานหรือความต้องการจากผู้จัดการพื้นที่ | Report Fields และ Filter Criteria     | FR-07 / FR-08 Acceptance Criteria              |
| ยืนยันช่องทางและเงื่อนไข Notification            | Event + Channel + Timing              | FR-02 / FR-04 Notification AC                  |
