## 1. Introduction

### 1.1 Purpose
เอกสารประกอบความต้องการ ( Requirements )ของระบบแจ้งปัญหาพื้นที่ส่วนกลาง เพื่อให้ผู้พบเห็นปัญหาได้ แจ้งปัญหาและติดตามสถานะ ให้เจ้าหน้าที่ที่เกี่ยวข้องได้อย่างรวดเร็วและช่วยให้เจ้าหน้าที่รับผิดชอบสามารถรับเรื่อง ติดตามสถานะ จัดลำดับความสำคัญ และดำเนินการแก้ไขปัญหาที่เกิดขึ้นได้อย่างเป็นระบบและมีประสิทธิภาพมากยิ่งขึ้น

### 1.2 Scope
ระบบสามารถให้ผู้แจ้งปัญหาส่งรายงานการแจ้งปัญหาพื้นที่ส่วนกลางพร้อมระบุรายละเอียดที่จำเป็น ได้แก่ รูปภาพประกอบ อาคาร ตำแหน่งที่เกิดเหตุ และประเภทปัญหา เพื่อให้เจ้าหน้าที่สามารถตรวจสอบและดำเนินการแก้ไขได้อย่างถูกต้องและเหมาะสม นอกจากนี้ ระบบมีการรตรวจสอบและติดตามสถานะการดำเนินงาน การจัดลำดับความสำคัญของปัญหา การมอบหมายงานให้เจ้าหน้าที่ที่เกี่ยวข้องและการอัปเดตสถานะพร้อมบันทึกผลการดำเนินงาน เพื่อให้ผู้แจ้งปัญหาสามารถติดตามความคืบหน้าได้อย่างชัดเจน และช่วยให้การจัดการปัญหาพื้นที่ส่วนกลางเป็นไปอย่างเป็นระบบ มีประสิทธิภาพ และสามารถตรวจสอบประวัติการดำเนินงานย้อนหลังได้

## 2. Overall Description

### 2.1 Product Perspective
ระบบแจ้งปัญหาพื้นที่ส่วนกลางเป็นระบบสารสนเทศที่พัฒนาขึ้นเพื่อสนับสนุนกระบวนการแจ้งปัญหาและติดตามการแก้ไขปัญหาภายในพื้นที่ส่วนกลาง โดยทำหน้าที่เป็นช่องทางกลางในการสื่อสารและจัดการข้อมูลระหว่างผู้แจ้งปัญหา เจ้าหน้าที่ และผู้ดูแลระบบ ระบบรองรับการแจ้งปัญหาพร้อมรายละเอียดที่จำเป็น การติดตามสถานะการดำเนินงาน และการอัปเดตข้อมูลของรายการแจ้งปัญหา เพื่อให้การจัดการปัญหาเป็นไปอย่างมีระบบและสามารถตรวจสอบข้อมูลย้อนหลังได้

ระบบแบ่งการทำงานตามบทบาทของผู้ใช้งาน ได้แก่ ผู้แจ้งปัญหาสามารถส่งรายงานและติดตามสถานะการดำเนินงาน เจ้าหน้าที่สามารถตรวจสอบรายการแจ้งปัญหาและอัปเดตสถานะ และผู้ดูแลระบบสามารถค้นหาและตรวจสอบประวัติการดำเนินงานย้อนหลัง ทั้งนี้ ระบบมุ่งเน้นการจัดการข้อมูลการแจ้งปัญหาและการติดตามกระบวนการดำเนินงาน โดยไม่ครอบคลุมกระบวนการจัดซื้อวัสดุและการจัดการงานซ่อมบำรุงนอกระบบ

## 5. External Interface Requirements

### 5.1 User Interfaces

1. **ส่วนติดต่อสำหรับผู้แจ้ง**
   - **หน้าแจ้งปัญหาพื้นที่ส่วนกลาง:** แบบฟอร์มขั้นตอนเดียวสำหรับแจ้งปัญหา ประกอบด้วยการเลือกอาคาร, ระบุชั้นและตำแหน่งที่เกิดเหตุ, เลือกประเภทของปัญหา, ระบุรายละเอียดปัญหา, ช่องทำเครื่องหมายกรณีเป็นเหตุเสี่ยงด้านความปลอดภัย และปุ่มแนบรูปภาพประกอบอย่างน้อย 1 รูป
   - **หน้าติดตามสถานะและผลการดำเนินงาน:** แสดงรายการที่เคยแจ้ง พร้อมหมายเลขอ้างอิงคำร้อง, สถานะปัจจุบัน และผลการดำเนินงาน
   - **การแจ้งเตือนบนระบบ:** แสดงข้อความแจ้งเตือนเมื่อสถานะของรายการแจ้งปัญหามีการเปลี่ยนแปลง

2. **ส่วนติดต่อสำหรับเจ้าหน้าที่**
   - **หน้ารายการแจ้งปัญหาและค้นหา:** แสดงรายการแจ้งปัญหาทั้งหมด รองรับการค้นหาและกรองข้อมูลตามประเภทปัญหา อาคาร และระดับความเร่งด่วน
   - **หน้าตรวจสอบรายละเอียดและอัปเดตงาน:** แสดงรายละเอียดและรูปภาพของปัญหา, ฟังก์ชันรวมรายการแจ้งปัญหาที่ซ้ำซ้อน, ฟอร์มเปลี่ยนสถานะและบันทึกผลการทำงาน และการมอบหมาย/โอนย้ายงานให้ผู้รับผิดชอบ
   - **หน้าต่างแจ้งเตือนเหตุเร่งด่วนด้านความปลอดภัย:** แสดงการแจ้งเตือนทันทีพร้อมระบุตำแหน่งของเหตุเสี่ยงด้านความปลอดภัยอย่างชัดเจน

3. **ส่วนติดต่อสำหรับผู้ดูแลระบบ**
   - **หน้าจัดการสิทธิ์และบัญชีผู้ใช้:** จัดการกำหนดบทบาทและสิทธิ์การเข้าถึงข้อมูลตาม 3 บทบาท (ผู้แจ้ง, เจ้าหน้าที่, ผู้ดูแลระบบ)
   - **หน้าตรวจสอบประวัติการดำเนินงานย้อนหลัง** ค้นหาและดูประวัติการดำเนินงาน วันเวลา ผู้ดำเนินการ และรายละเอียดการเปลี่ยนแปลง โดยไม่สามารถแก้ไขหรือลบได้
   - **หน้ารายงานสรุปสถิติภาพรวม:** เรียกดูและสรุปสถิติข้อมูลการแจ้งปัญหาตามช่วงเวลา อาคาร และประเภทปัญหา

### 5.2 Software / External System Interfaces

1. **University Identity Service:**
   - **หน้าที่:** ระบบตรวจสอบบัญชีผู้ใช้ของมหาวิทยาลัย
   - **การเชื่อมต่อ:** ส่งคำขอตรวจสอบบัญชีผู้ใช้และบทบาท เพื่อรองรับการยืนยันตัวตนและการกำหนดสิทธิ์การใช้งานของผู้แจ้ง เจ้าหน้าที่ และผู้ดูแลระบบ

2. **Notification Service:**
   - **หน้าที่:** ระบบบริการแจ้งเตือน
   - **การเชื่อมต่อ:** รับข้อมูลการแจ้งเตือนจากระบบเพื่อส่งข้อความแจ้งเตือนไปยังผู้แจ้งเมื่อสถานะคำร้องเปลี่ยนแปลง และแจ้งเตือนเจ้าหน้าที่ทันทีเมื่อเกิดเหตุที่มีความเสี่ยงด้านความปลอดภัย

### 5.3 Data Interfaces

1. **ข้อมูลการแจ้งปัญหา**
   - รายละเอียดปัญหา, รูปภาพประกอบ, อาคาร, ตำแหน่ง/ชั้น/ห้องที่เกิดเหตุ, ประเภทปัญหา, และข้อมูลผู้แจ้ง
2. **ข้อมูลผลการแจ้งและติดตาม**
   - หมายเลขอ้างอิงคำร้อง, สถานะปัจจุบัน, ความคืบหน้าการดำเนินงาน, และข้อความแจ้งเตือน
3. **ข้อมูลการดำเนินงานของเจ้าหน้าที่**
   - การรับเรื่อง, การเปลี่ยนสถานะคำร้อง, การบันทึกผลการดำเนินงาน, และการมอบหมาย/โอนย้ายผู้รับผิดชอบ
4. **ข้อมูลรายการและลำดับความสำคัญ**
   - รายการคำร้อง, รายละเอียดปัญหา, ตำแหน่งเหตุเสี่ยง, และลำดับความสำคัญของงาน
5. **ข้อมูลการบริหารจัดการและตรวจสอบ**
   - ข้อมูลบัญชีผู้ใช้, สิทธิ์การเข้าถึง, ข้อมูลระบบ, รายงานสรุปสถิติภาพรวม, และประวัติการดำเนินงานย้อนหลัง
6. **ข้อมูลการเชื่อมต่อระบบภายนอก**
   - ข้อมูลคำขอตรวจสอบบัญชีผู้ใช้และบทบาท
   - ข้อมูลการแจ้งเตือนสถานะและเหตุเร่งด่วน

## 6. Business Rules

| ID | Rule | Related Requirement |
|---|---|---|
| **BR-01** | **ข้อมูลจำเป็นในการส่งรายงาน:** ผู้แจ้งต้องกรอกรายละเอียดปัญหา เลือกอาคาร ระบุตำแหน่งที่เกิดเหตุ เลือกประเภทของปัญหา และแนบรูปภาพประกอบอย่างน้อย 1 รูป ก่อนส่งรายงานสำเร็จ | FR-01 (FR-CAR-01, FR-CAR-02, AC-01) |
| **BR-02** | **การออกหมายเลขอ้างอิงและสถานะเริ่มต้น:** เมื่อส่งรายงานสำเร็จ ระบบต้องสร้างหมายเลขอ้างอิงที่ไม่ซ้ำกัน และแสดงให้ผู้แจ้งทราบทันที พร้อมกำหนดสถานะเริ่มต้นของรายการ | FR-01, FR-02 (FR-CAR-03, FR-CAR-04, AC-01) |
| **BR-03** | **การรวมรายการแจ้งปัญหาที่ซ้ำซ้อน:** หากพบรายการแจ้งปัญหาที่มีตำแหน่งเกิดเหตุและช่วงเวลาใกล้เคียงกัน เจ้าหน้าที่สามารถรวมรายการเข้าด้วยกันได้ โดยยังคงจัดเก็บข้อมูล รายละเอียด และรายชื่อของผู้แจ้งแต่ละรายไว้ครบถ้วน | FR-03 (FR-CAR-01, RC-03, AC-05) |
| **BR-04** | **การแจ้งเตือนเหตุเร่งด่วนด้านความปลอดภัย:** เมื่อระบบตรวจพบรายการแจ้งปัญหาที่เข้าข่ายความเสี่ยงด้านความปลอดภัย ระบบต้องจัดเป็นเหตุเร่งด่วน แสดงตำแหน่งที่เกิดเหตุอย่างชัดเจน และแจ้งเตือนเจ้าหน้าที่ผู้รับผิดชอบทันที | FR-04 (FR-CAR-10, FR-CAR-11, RC-04, AC-07) |
| **BR-05** | **การอัปเดตสถานะและการบันทึกผลการดำเนินงาน:** เมื่อเจ้าหน้าที่ดำเนินการแก้ไขหรือเปลี่ยนสถานะของรายการต้องบันทึกผลการทำงาน และระบบต้องแจ้งเตือนผู้แจ้งเมื่อสถานะเปลี่ยน | FR-02, FR-06 (FR-CAR-06, FR-CAR-07, FR-CAR-09, AC-02, AC-04) |
| **BR-06** | **การมอบหมายและการโอนย้ายงาน:** เจ้าหน้าที่สามารถระบุผู้รับผิดชอบหรือโอนย้ายงานตามประเภทของปัญหาได้ โดยระบบต้องแสดงผู้รับผิดชอบปัจจุบันและบันทึกประวัติการมอบหมาย | FR-06 (FR-CAR-08, RC-07, AC-06) |
| **BR-07** | **การควบคุมสิทธิ์และการบันทึกประวัติย้อนหลัง:** ระบบต้องบันทึกประวัติการดำเนินงานทุกขั้นตอน โดยไม่อนุญาตให้แก้ไขหรือลบ และต้องควบคุมสิทธิ์การเข้าถึงข้อมูลตามบทบาทของผู้ใช้ | FR-05 (FR-CAR-07, NFR-CAR-03, RC-05, RC-06, AC-09, AC-10) |
