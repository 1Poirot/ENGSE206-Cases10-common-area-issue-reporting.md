# 05 — Requirement Backlog and Prioritization

> **Week 5 deliverable**  
> Requirement ต้องระบุได้ ตรวจสอบได้ และเชื่อมโยงกับ stakeholder/value ที่ชัดเจน

## 1. Prioritization Method

เลือกใช้วิธีหนึ่ง เช่น MoSCoW, Value vs Effort, Kano หรือวิธีที่อาจารย์กำหนด

- วิธีที่ใช้: MoSCoW
- หลักเกณฑ์: พิจารณาจากความจำเป็นต่อกระบวนการหลักของระบบ คุณค่าต่อผู้ใช้งาน ผลกระทบหากไม่มี Requirement และ Dependency กับ Requirement อื่น

    - M - Must: จำเป็นต่อการทำงานหลักของระบบ (ขาดไม่ได้เด็ดขาด)
    - S - Should: มีความสำคัญ แต่ระบบยังทำงานหลักได้หากไม่มี (สำคัญแต่ไม่ถึงขั้นวิกฤต)
    - C - Could: เพิ่มความสะดวก แต่ไม่จำเป็นต่อระบบหลัก (มีก็ดี ไม่มีก็ได้)
    - W - Won't: ยังไม่พัฒนาใน Release ปัจจุบัน (ครั้งนี้ยังไม่ทำ)
