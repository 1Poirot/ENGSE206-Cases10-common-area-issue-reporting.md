## 4. Use Case Specification

### UC-01 — [แจ้งปัญหาพื้นที่ส่วนกลาง]

| Field | Detail |
|---|---|
| Primary Actor | [ผู้แจ้ง] |
| Trigger | [ผู้แจ้งต้องการแจ้งปัญหาที่เกิดขึ้นในพื้นที่ส่วนกลาง] |
| Preconditions | [ผู้แจ้งเข้าสู่หน้าการแจ้งปัญหาและสามารถกรอกข้อมูลรายการแจ้งปัญหาได้] |
| Main Success Scenario | 1. ผู้แจ้งกรอกรายละเอียดปัญหา <br> 2. ผู้แจ้งระบุอาคารและตำแหน่งที่เกิดเหตุ <br> 3. ผู้แจ้งเลือกประเภทของปัญหา <br> 4. ผู้แจ้งแนบรูปภาพประกอบอย่างน้อย 1 รูป <br> 5. ผู้แจ้งส่งรายการแจ้งปัญหา <br> 6. ระบบตรวจสอบข้อมูลที่จำเป็น <br> 7. ระบบบันทึกรายการแจ้งปัญหา <br> 8. ระบบสร้างหมายเลขอ้างอิงที่ไม่ซ้ำกัน <br> 9. ระบบแสดงหมายเลขอ้างอิงให้ผู้แจ้งทราบ |
| Alternate / Exception Flows | [1. หากกรอกข้อมูลไม่ครบ ระบบแจ้งเตือนให้กรอกข้อมูลที่จำเป็นให้ครบ <br> 2. หากไม่มีรูปภาพแนบ ระบบแจ้งเตือนให้แนบรูปภาพอย่างน้อย 1 รูป <br> 3. หากบันทึกรายการไม่สำเร็จ ระบบแจ้งข้อผิดพลาดและให้ผู้แจ้งลองใหม่] |
| Postconditions | [รายการแจ้งปัญหาถูกบันทึกสำเร็จและมีหมายเลขอ้างอิงที่ไม่ซ้ำกัน] |
| Related Requirements | FR-01 |

### UC-02 — [ติดตามสถานะและผลดำเนินการ]

| Field | Detail |
|---|---|
| Primary Actor | [ผู้แจ้งต้องการตรวจสอบความคืบหน้าของรายการแจ้งปัญหา] |
| Trigger | [ผู้แจ้งต้องการตรวจสอบความคืบหน้าของรายการแจ้งปัญหา] |
| Preconditions | [ผู้แจ้งมีรายการแจ้งปัญหาที่เคยส่งเข้าสู่ระบบ] |
| Main Success Scenario | 1. ผู้แจ้งเข้าสู่หน้าติดตามรายการแจ้งปัญหา <br> 2. ระบบแสดงรายการแจ้งปัญหาของผู้แจ้ง <br> 3. ผู้แจ้งเลือกรายการที่ต้องการติดตาม <br> 4. ระบบแสดงสถานะปัจจุบันและผลการดำเนินงานของรายการ |
| Alternate / Exception Flows | [1. หากไม่พบรายการแจ้งปัญหา ระบบแสดงข้อความแจ้งว่าไม่พบรายการ <br> 2. หากไม่สามารถโหลดข้อมูลได้ ระบบแจ้งข้อผิดพลาด] |
| Postconditions | [ผู้แจ้งทราบสถานะและความคืบหน้าของรายการแจ้งปัญหา] |
| Related Requirements | FR-02 |

### UC-03 — [ตรวจสอบปัญหาที่ซ้ำซ้อนและรวมปัญหา]

| Field | Detail |
|---|---|
| Primary Actor | [เจ้าหน้าที่] |
| Trigger | [เจ้าหน้าที่พบรายการแจ้งปัญหาที่อาจเป็นปัญหาเดียวกัน] |
| Preconditions | [มีรายการแจ้งปัญหาในระบบและเจ้าหน้าที่สามารถเข้าถึงรายการได้] |
| Main Success Scenario | 1. เจ้าหน้าที่ค้นหารายการแจ้งปัญหาที่เกี่ยวข้อง <br> 2. ระบบแสดงรายการที่ตรงกับข้อมูลค้นหา <br> 3. เจ้าหน้าที่ตรวจสอบรายละเอียดของรายการ <br> 4. เจ้าหน้าที่เลือกยืนยันรายการที่ซ้ำซ้อน <br> 5. เจ้าหน้าที่สั่งรวมรายการที่ซ้ำกัน <br> 6. ระบบรวมข้อมูลรายการและรักษาข้อมูลของผู้แจ้งแต่ละรายไว้ |
| Alternate / Exception Flows | [1. หากไม่พบรายการซ้ำ เจ้าหน้าที่ดำเนินการโดยไม่รวมรายการ <br> 2. หากข้อมูลไม่เพียงพอ เจ้าหน้าที่ไม่ยืนยันการรวมรายการ <br> 3. หากรวมรายการไม่สำเร็จ ระบบแจ้งข้อผิดพลาด] |
| Postconditions | [รายการที่ซ้ำซ้อนถูกรวมเข้าด้วยกันและข้อมูลของผู้แจ้งยังคงถูกเก็บไว้] |
| Related Requirements | FR-03 |

### UC-04 — [ดูรายละเอียดรายการแจ้งปัญหา]

| Field | Detail |
|---|---|
| Primary Actor | [เจ้าหน้าที่] |
| Trigger | [เจ้าหน้าที่ต้องการตรวจสอบรายการแจ้งปัญหาเพื่อดำเนินการ] |
| Preconditions | [มีรายการแจ้งปัญหาในระบบและเจ้าหน้าที่มีสิทธิ์เข้าถึงข้อมูล] |
| Main Success Scenario | 1. เจ้าหน้าที่เข้าสู่หน้ารายการแจ้งปัญหา <br> 2. เจ้าหน้าที่ค้นหารายการตามข้อมูลที่ต้องการ <br> 3. เจ้าหน้าที่กรองรายการตามประเภท อาคาร หรือระดับความเร่งด่วน <br> 4. เจ้าหน้าที่เลือกรายการแจ้งปัญหา <br> 5. ระบบแสดงรายละเอียดของรายการ เช่น รายละเอียดปัญหา รูปภาพ อาคาร ตำแหน่ง และประเภทปัญหา |
| Alternate / Exception Flows | [1. หากไม่พบรายการที่ตรงกับเงื่อนไข ระบบแจ้งว่าไม่พบข้อมูล <br> 2. หากเจ้าหน้าที่ไม่มีสิทธิ์เข้าถึงข้อมูล ระบบปฏิเสธการเข้าถึง] |
| Postconditions | [เจ้าหน้าที่สามารถดูรายละเอียดรายการแจ้งปัญหาที่ต้องการได้] |
| Related Requirements | FR-05 |

### UC-05 — [ดำเนินการแก้ไขปัญหา]

| Field | Detail |
|---|---|
| Primary Actor | [เจ้าหน้าที่] |
| Trigger | [เจ้าหน้าที่ได้รับมอบหมายให้ดำเนินการแก้ไขรายการแจ้งปัญหา] |
| Preconditions | [มีรายการแจ้งปัญหาที่เจ้าหน้าที่สามารถดำเนินการได้] |
| Main Success Scenario | 1. เจ้าหน้าที่เปิดรายการแจ้งปัญหา <br> 2. เจ้าหน้าที่ตรวจสอบรายละเอียดของปัญหา <br> 3. เจ้าหน้าที่ดำเนินการแก้ไขปัญหา <br> 4. เจ้าหน้าที่เปลี่ยนสถานะของรายการ <br> 5. เจ้าหน้าที่บันทึกผลการดำเนินงาน <br> 6. ระบบบันทึกข้อมูลการดำเนินงาน |
| Alternate / Exception Flows | [1. หากไม่สามารถดำเนินการแก้ไขได้ เจ้าหน้าที่คงสถานะรายการและบันทึกเหตุผล <br> 2. หากบันทึกข้อมูลไม่สำเร็จ ระบบแจ้งข้อผิดพลาด] |
| Postconditions | [สถานะและผลการดำเนินงานของรายการแจ้งปัญหาถูกบันทึกในระบบ] |
| Related Requirements | FR-06,FR-07 |

### UC-06 — [รับการแจ้งเตือนเหตุด้านความปลอดภัย]

| Field | Detail |
|---|---|
| Primary Actor | [ผู้ดูแลรักษาความปลอดภัย] |
| Trigger | [รายการแจ้งปัญหาถูกจัดอยู่ในระดับที่เข้าข่ายความเสี่ยงด้านความปลอดภัย] |
| Preconditions | [ระบบสามารถจำแนกระดับความเร่งด่วนของรายการแจ้งปัญหาได้] |
| Main Success Scenario | 1. ระบบตรวจพบว่ารายการเข้าข่ายความเสี่ยงด้านความปลอดภัย <br> 2. ระบบส่งการแจ้งเตือนไปยังผู้ดูแลรักษาความปลอดภัยทันที <br> 3. ผู้ดูแลรักษาความปลอดภัยเปิดการแจ้งเตือน <br> 4. ระบบแสดงรายละเอียดและตำแหน่งของเหตุ <br> 5. ผู้ดูแลรักษาความปลอดภัยเข้าพื้นที่เพื่อระงับเหตุ |
| Alternate / Exception Flows | [1. หากไม่เข้าข่ายความเสี่ยงด้านความปลอดภัย ระบบไม่ส่งการแจ้งเตือนด้านความปลอดภัย <br> 2. หากการแจ้งเตือนไม่สำเร็จ ระบบบันทึกเหตุการณ์เพื่อดำเนินการตามช่องทางที่กำหนด] |
| Postconditions | [ผู้ดูแลรักษาความปลอดภัยได้รับข้อมูลเหตุและตำแหน่งเพื่อดำเนินการระงับเหตุ] |
| Related Requirements | FR-11 |

### UC-08 — [ดูรายงานสรุปสถิติ]

|---|---|

| Preconditions | [ระบบมีการบันทึกประวัติการดำเนินงานและผู้ดูแลระบบมีสิทธิ์เข้าถึงข้อมูล] |
| Main Success Scenario | 1. ผู้ดูแลระบบเข้าสู่หน้าประวัติการดำเนินงาน <br> 2. ระบบแสดงข้อมูล Audit Log <br> 3. ผู้ดูแลระบบค้นหาหรือกรองข้อมูลตามเงื่อนไขที่ต้องการ <br> 4. ผู้ดูแลระบบเลือกประวัติที่ต้องการตรวจสอบ <br> 5. ระบบแสดงรายละเอียดการดำเนินงานย้อนหลัง |
| Alternate / Exception Flows | [1. หากไม่พบข้อมูลตามเงื่อนไข ระบบแจ้งว่าไม่พบข้อมูล <br> 2. หากผู้ใช้งานไม่มีสิทธิ์ ระบบปฏิเสธการเข้าถึง] |
| Postconditions | [ผู้ดูแลระบบสามารถตรวจสอบประวัติการดำเนินงานย้อนหลังได้] |
| Related Requirements | FR-10 |

### UC-10 — [จัดการบทบาทและสิทธิ์ผู้ใช้งาน]

| Field | Detail |
|---|---|
| Primary Actor | [ผู้ดูแลระบบ] |
| Trigger | [ผู้ดูแลระบบต้องการกำหนดหรือแก้ไขสิทธิ์การเข้าถึงของผู้ใช้งาน] |
| Preconditions | [ผู้ดูแลระบบเข้าสู่ระบบและมีสิทธิ์ในการจัดการบทบาทและสิทธิ์] |
| Main Success Scenario | 1. ผู้ดูแลระบบเข้าสู่หน้าจัดการบทบาทและสิทธิ์ <br> 2. ระบบแสดงกลุ่มผู้ใช้งานและบทบาทที่กำหนด <br> 3. ผู้ดูแลระบบเลือกผู้ใช้งานหรือกลุ่มผู้ใช้งาน <br> 4. ผู้ดูแลระบบกำหนดหรือแก้ไขบทบาทและสิทธิ์ <br> 5. ผู้ดูแลระบบยืนยันการเปลี่ยนแปลง <br> 6. ระบบบันทึกสิทธิ์การเข้าถึง <br> 7. ระบบใช้สิทธิ์ใหม่ในการควบคุมการเข้าถึงข้อมูลและฟังก์ชัน |
| Alternate / Exception Flows | [1. หากกำหนดสิทธิ์ไม่ถูกต้อง ระบบแจ้งเตือนให้แก้ไข <br> 2. หากบันทึกการเปลี่ยนแปลงไม่สำเร็จ ระบบแจ้งข้อผิดพลาด <br> 3. หากผู้ดูแลระบบไม่มีสิทธิ์ในการจัดการ ระบบปฏิเสธการดำเนินการ] |
| Postconditions | [ระบบบันทึกบทบาทและสิทธิ์ของผู้ใช้งาน และนำไปใช้ควบคุมการเข้าถึง] |
| Related Requirements | FR-12 |
